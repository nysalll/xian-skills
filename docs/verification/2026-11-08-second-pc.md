# 2026-11-08 第二台电脑安装反馈

这台电脑是 Windows + MuMu 12。腾讯 WorkBuddy 从 GitHub 安装了 xian-skills，并建立了独立虚拟环境。它不依赖原来的研究工作区。

当时已经做到：

- 识别 MuMu 和正式服
- 完整同步 1109 个文件
- 解密 196 个 Lua Bundle，得到 6617 个 LuaJIT 资源
- 导出 44 张 PNG
- 13 项单元测试通过

随后暴露的问题，和这次代码里的对应处理：

| 反馈 | 处理 |
| --- | --- |
| 没有反编译器，玩家不会自己找 GitHub Release | `xian tools decompiler` 展示 MIT 许可证、`Mar_24_2024` 和 SHA256。只有 `--install --yes` 才下载 |
| WorkBuddy 要手抄到 `~/.workbuddy/skills/`，还改了技能里的绝对路径 | 安装器只写这个目录和项目 `.workbuddy/skills/`。ZIP 顶层就是技能文件夹。调用固定走 `%USERPROFILE%\.xian-skills\bin\xian.cmd` |
| 技能被装进 `.codebuddy/` | WorkBuddy 不再使用 `.codebuddy`。那是另一个产品的目录 |
| SDK ADB 34 和 MuMu ADB 36 抢服务，设备反复 offline | 已有 adb 进程时继续用它。offline 会停下来说明，不自动换另一个 adb.exe |
| 只说检查环境，却开始了整包同步 | 技能和 `--yes` 提示都写明：检查环境、读取版本不是复制文件、抓包或进程探测的授权 |
| 版本号、快照份数和 version.txt 行数混在一起 | 状态里分开写当前版本、完整快照份数和 version.txt 行数 |

这些修复还没有在那台电脑上再跑一遍。上面的使用结果是反馈，不是这次提交里附带的数据。
